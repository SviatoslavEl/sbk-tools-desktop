# Целевая архитектура

## Границы продукта

Продукт объединяет прикладные инструменты в общей desktop-оболочке. Базы модулей разделены. Единственная межмодульная функция — явный подбор разрешённых к раскрытию записей опыта и сотрудников для карточки закупки; он не изменяет источники и требует выбора пользователя.

```text
React UI
  ├─ calculator
  ├─ scanner
  ├─ contract-experience
  ├─ staff
  ├─ procurement
  ├─ tender-calendar
  └─ dashboard (read-only overview)
        │ Tauri invoke/events
        ▼
Rust/Tauri host
  ├─ workspace и миграции
  ├─ системные файловые диалоги
  ├─ backup/restore
  └─ управление Python worker
        │ локальный версионированный протокол
        ▼
ScanDocument worker
  ├─ PDFium / Pillow / NumPy
  ├─ LibreOffice для DOCX
  └─ Tesseract OCR
```

## Контур закупки 2.1

Новая карточка разделена на доменные правила, прикладные сценарии и презентационные компоненты. Go/No-Go, денежный поток, сценарии участия, конфликты загрузки, устаревание доказательств и договорные правила рассчитываются детерминированно в `src/modules/procurement/domain.ts`. React только собирает подтверждённый пользователем ввод и показывает основания результата.

PDF, DOCX и XLSX проходят локальную проверку magic/MIME, получают SHA-256 и неизменяемый `versionId`. Текст хранится фрагментами с указанием страницы, раздела, листа или диапазона ячеек. Замена документа не перезаписывает старую версию и помечает связанные доказательства устаревшими.

## Intelligence boundary

```text
React → typed Tauri IPC → Rust intelligence gateway → DisabledProvider
                                                ↘ будущий LocalApiProvider
```

Сейчас доступен только `DisabledProvider`; он не выполняет сетевых запросов и не влияет на ручные функции. `MockProvider` существует только в тестах. Контракт будущего сервера находится в `contracts/intelligence/v1`. Очередь, артефакты, предложения и evidence отделены от подтверждённых бизнес-данных в SQLite. Секрет в базе отсутствует: разрешена только ссылка на системное хранилище учётных данных.

## Хранение

Каждый модуль получает отдельную базу либо строго изолированную схему. Rust является единственным владельцем структурированного хранилища. Python worker получает снимок параметров конкретного задания и не открывает базы приложения.

Все пути внутри portable workspace относительные. Перед миграцией схемы создаётся резервная копия. Одновременное открытие одного workspace двумя экземплярами запрещается блокировкой.

## Обработка документов

React вызывает команды Tauri. Rust проверяет пути и запускает отдельный worker на задание. Прогресс передаётся событиями, отмена не должна оставлять частичный пользовательский файл. Локальный HTTP-сервер не используется.

## Упаковка

- Windows portable: прежний `ScanDocument.exe` — Rust-launcher с `asInvoker`, который распаковывает приложение, фиксированный WebView2, OCR, LibreOffice и модели в уникальную временную папку и очищает её после завершения.
- Windows installed: независимый NSIS-пакет «СБК Инструменты — быстрый запуск» (`ru.sbk.tools.fast`) устанавливает те же закреплённые компоненты для текущего пользователя и запускает `SBK-Tools-Fast.exe` напрямую из каталога установки. Portable launcher в этот пакет не входит.
- macOS: отдельные arm64 и x86_64 `.app` на первом этапе.
- Тяжёлые компоненты запускаются только при работе со сканером.
- LibreOffice закреплён на версии 26.2.5 и проверяется по SHA-256 перед упаковкой.

Оба Windows-варианта используют одну логику выбора `SBKTools/ProductData`, один файл указателя рабочей папки и одну файловую блокировку редактора. Каталог установки не является хранилищем пользовательских данных. Обновление и удаление установленного приложения не мигрирует и не удаляет рабочую папку.

Окно Tauri создаётся до проверки рабочей папки. Rust выполняет открытие workspace, семи SQLite-баз и восстановление локальной очереди в фоновом потоке; React показывает полученный этап. Команды данных становятся доступны только после статуса «Готово». Ошибка сетевой папки остаётся в видимом окне и допускает повторную проверку или выбор другого расположения.

## Безопасность

- Исходные документы никогда не изменяются.
- Логи не содержат документы, OCR-текст и персональные данные.
- Вложения сначала попадают в отдельный staging и закрепляются только одной транзакцией с карточкой.
- Резервные копии проверяются до восстановления и могут шифроваться Argon2id + XChaCha20-Poly1305.
- CSP запрещает внешние ресурсы.
- Все импорты проходят предпросмотр до записи.
- Деструктивные действия подтверждаются и по возможности заменяются архивированием.

## Календарь тендеров 2.2

Раздел `tender-calendar` хранится в отдельной локальной базе и ссылается на закупки и кадровые карточки по идентификаторам. План содержит сложность, трудоёмкость, внутренний срок, назначения и контрольные точки. Детерминированный модуль рекомендаций сравнивает требуемые навыки с квалификацией и опытом сотрудника, затем учитывает его уже назначенную загрузку и период доступности. Решение о назначении всегда принимает пользователь.
