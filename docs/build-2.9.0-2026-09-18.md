Windows-задание `105632922812` остановилось на четырёх Rust-регрессиях:

- Три snapshot-теста ошибочно пытались читать открытым заново дескриптором
  собственные byte-range lockfiles: Windows error 33. Исправлен только тестовый
  reader с read-only mapped view для точных lockfile-путей. Побайтовые проверки
  и удержание блокировки сохранены; произвольные ошибки не пропускаются.
- Экспорт реестра действительно мог заменить существующий ZIP: `fs::rename`
  на Windows допускает замену. Публикация КП и реестров теперь использует общий
  no-replace helper; добавлены проверки занятого имени, гонки двух экспортов,
  ошибок назначения и длинных Windows-путей. Подтверждение семантики:
  [Rust rename](https://doc.rust-lang.org/std/fs/fn.rename.html),
  [Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).
- Windows Rust-проверки перенесены перед компиляцией worker, без исключения
  тестов или ослабления остановки при ошибке. Порядок защищён контрактными тестами.

Windows-установщик в прогоне 70 не создан, выпуск не публиковался.
Mac-пакет прогона 70 — не окончательный кандидат после найденного исправления;
