# Конструктор коммерческих предложений — контракт первой версии

Дата: 18 сентября 2026. Статус: спецификация для реализации, не готовая функция.
Основа: v2.8.9 (`c5841e8`). Сервер не требуется. Windows и macOS имеют одинаковые сценарии.

## 1. Что уже есть и что добавляем

В закупках уже есть простые HTML-КП по шагам переторжки (`Procurement.tsx`,
`exportOffers`) и шаблон `SBK-PROCUREMENT/1`. Это не новый конструктор.
Добавляем отдельный инструмент **«Коммерческие предложения»**: реестр,
редактор позиций и условий, сохраняемые шаблоны, клиентский предпросмотр,
выгрузка DOCX/PDF и переходы из калькулятора/закупки.

Граница первой версии: RUB, русский интерфейс, A4, локальная генерация.
Не входят: отправка почты/на площадку, электронная подпись, CRM, произвольный
HTML/JavaScript, импорт пользовательских DOCX-шаблонов, юридическая проверка
полномочий, автоматическое применение факсимиле. Старый экспорт не удалять;
пометить как «КП по шагам · HTML» и дать переход к конструктору.

## 2. Пользовательские сценарии и готовые defaults

### Реестр

- Поиск по номеру, названию, исполнителю, заказчику и закупке; фильтры по
  статусу/компании/дате. Столбцы: номер и версия, дата, заказчик, предмет,
  итог с НДС, статус, срок действия. Компактная таблица, отдельная прокрутка.
- Действия: создать, открыть, создать копию, новая редакция, история,
  архивировать/восстановить. Массовые действия только по чекбоксам с точным
  перечнем и подтверждением. Никакого удаления источников при удалении КП.
- Статусы: «Черновик», «Готово», «Отправлено», «Принято», «Отклонено».
  «Отправлено» — только ручная отметка; приложение ничего не отправляет.

### Редактор: пять шагов, доступных также напрямую

1. **Кому и от кого** — дата, номер, предмет, исполнитель, заказчик, адресат.
2. **Позиции и цена** — строки, единицы, количество, цены, скидка, НДС, итоги.
3. **Условия и подпись** — сроки работ/поставки, оплата, срок действия,
   контакты, подписант, явно выбранные приложения.
4. **Оформление** — шаблон, показываемые блоки, акцент, логотип.
5. **Проверка и экспорт** — ошибки, предупреждения, страницы клиентского
   документа, DOCX/PDF, фактический путь результата и «Открыть папку».

На широком окне справа предпросмотр; на узком — отдельная вкладка
«Редактор / Предпросмотр», без наложения панелей. Позиции сворачиваются в строку.
Новая строка раскрыта; ввод не сворачивает её; ошибка раскрывает нужную строку.

Defaults: дата — локальная сегодня; номер `КП-ГГГГММДД-<6 символов UUID>`
(редактируемый, не обещает сквозную бухгалтерскую нумерацию); срок действия
30 календарных дней от даты; валюта RUB; стандартный шаблон; одна пустая
позиция, количество 1, единица «усл.»; цена не задана, НДС «Без НДС».
Отсутствующие реквизиты, банковские сведения и ФИО никогда не придумываются.
Оплата и сроки пустые с понятными подсказками, не юридические обязательства по умолчанию.

### Переход из калькулятора

Кнопка «Создать КП» передаёт текущий валидный расчёт, включая ещё не сохранённые
значения, без изменения калькулятора. Предложить одну строку с названием расчёта,
количеством 1, **вычисленной `calculate(data).priceGross`**, а не устаревшей
`proposedPrice` в режиме расчёта от маржи. НДС — `priceVatRate`, база — с НДС.
Сначала округлить предлагаемую цену до копеек и показать эту цену пользователю.
Переносятся только цена, ставка и безопасное название; не себестоимость/маржа.
Если расчёт невалиден — переход не создаёт КП и ведёт к ошибке. Убыточный
расчёт требует явного подтверждения, предупреждение остаётся только в редакторе.

### Переход из закупки

Кнопка «Создать КП»: предмет/заказчик/номер закупки из текущей карточки;
источник цены пользователь выбирает из связанных снимков расчёта или ценовых
сценариев. При нескольких вариантах не выбирать первый молча. НМЦ не становится
нашей ценой автоматически. Без выбранного источника цена остаётся незаполненной.
Для снимка калькулятора использовать его расчётную цену, а не текущую запись реестра.
Действие не изменяет закупку; обратная ссылка в КП — справочная, по ID источника.
При незавершённом КП новый handoff спрашивает «Сохранить / Заменить / Отмена».

## 3. Parties, контакты и подписант

- Исполнитель выбирается из неархивных внутренних компаний; заказчик — из
  неархивных внешних, с явной возможностью выбрать любую компанию или заполнить
  реквизиты вручную. В уже созданном КП архивирование компании не уничтожает снимок.
- Копируются снимки названия, ИНН/КПП/ОГРН, адреса, контакта; реквизиты можно
  уточнить **в КП**, это не редактирует справочник. ID и дата источника хранятся отдельно.
- Адресат выбирается из `decisionMakers` либо вводится: ФИО, должность,
  телефон, email. Общий контакт компании не заменяет явно выбранного адресата.
- Подписант: ФИО, должность, основание полномочий. Из `authorizedSigners`
  предлагаются доверенности с датой выдачи/окончания. Просроченная, ещё не
  действующая либо без даты — предупреждение, не заявление о действительности.
  Пользователь может выбрать руководителя/ручное основание отдельно.
- Доверенность не прикладывается автоматически. Файл добавляется только явным
  чекбоксом; показываются имя, дата, источник и размер. Проверяется существование
  файла перед экспортом. По умолчанию КП без приложений и без изображений подписи.
- Банковских реквизитов в текущем `CompanyCard` нет: первая версия допускает
  отдельный необязательный текстовый блок реквизитов КП, без изменения CompanyCard.

## 4. Контракт данных

Типы концептуальные; имена фиксируют границы хранения/экспорта.

```ts
type DecimalText = string; // нормализованное десятичное число, без экспоненты
type ProposalStatus = 'draft' | 'ready' | 'sent' | 'accepted' | 'rejected';
type Tax = { kind: 'none' } | { kind: 'vat'; rate: 0 | 5 | 7 | 10 | 11 | 20 | 22 };
interface PartySnapshot {
  companyId?: string; sourceUpdatedAt?: string;
  name: string; shortName: string; inn: string; kpp: string; ogrn: string;
  address: string; contact: string; paymentDetails: string;
}
interface ProposalContact { fullName: string; position: string; phone: string; email: string }
interface ProposalSigner extends ProposalContact {
  basis: string; issuedAt: string; expiresAt: string; sourceSignerId?: string;
}
interface ProposalLine {
  id: string; title: string; description: string; unit: string;
  quantity: DecimalText; unitPrice: DecimalText; // quantity ≤ 6, price ≤ 4 decimals
  priceBasis: 'gross' | 'net'; discountPercent: DecimalText; tax: Tax;
}
interface ProposalSource {
  tool: 'calculator' | 'procurement'; recordId?: string;
  sourceRevision?: string; capturedAt: string; wasUnsaved: boolean;
  priceOrigin: string; // нейтральная подпись для редактора, не наружного документа
}
interface ProposalTemplate {
  schemaVersion: 1; id: string; version: number; name: string;
  style: 'standard' | 'compact'; accentColor: string;
  logo?: AttachmentInfo; // локальный PNG/JPEG, без активного содержимого
  show: { address: boolean; requisites: boolean; contact: boolean; signer: boolean };
  introduction: string; conclusion: string; footer: string;
}
interface ProposalData {
  kind: 'proposal'; schemaVersion: 1;
  number: string; documentDate: string; title: string; validUntil: string;
  currency: 'RUB'; status: ProposalStatus; revision: number; familyId: string;
  issuer: PartySnapshot; recipient: PartySnapshot; addressee: ProposalContact;
  contact: ProposalContact; signer?: ProposalSigner; lines: ProposalLine[];
  deliveryTerms: string; paymentTerms: string; introduction: string; conclusion: string;
  attachments: AttachmentInfo[]; template: ProposalTemplate; source?: ProposalSource;
  internalNote: string; // только редактор/общая база, никогда экспорт
}
interface ProposalPublicDocument {
  schemaVersion: 1; number: string; revision: number; documentDate: string;
  title: string; validUntil: string; currency: 'RUB';
  issuer: Omit<PartySnapshot, 'companyId' | 'sourceUpdatedAt'>;
  recipient: Omit<PartySnapshot, 'companyId' | 'sourceUpdatedAt'>;
  addressee: ProposalContact; contact: ProposalContact; signer?: Omit<ProposalSigner, 'sourceSignerId'>;
  // Только явно выбранные клиентские поля строк, посчитанные итоги и условия.
  lines: PublicLine[]; totals: PublicTotals; terms: PublicTerms; layout: PublicLayout;
}
```

`PublicLine`, `PublicTotals`, `PublicTerms`, `PublicLayout` — закрытые схемы,
не `Record<string, unknown>` и не spread исходной карточки. `PublicLine` содержит
только название/описание/единицу/количество/цену/скидку/НДС и рассчитанные суммы.
`PublicTotals` — итоги net/vat/gross в копейках и разбивка по ставкам;
`PublicTerms` — введённые клиентские тексты; `PublicLayout` — разрешённые
параметры шаблона и локальный проверенный логотип без ID источников.

## 5. Расчёт денег и проверки

- Десятичная арифметика, не `number` как источник денежных итогов. Ввод поддерживает
  запятую/точку и пробелы-разделители; нормализуется. NaN/Infinity/экспонента,
  отрицательные цены/количество, количество 0, скидка вне 0…100 блокируются.
- Цена до 4 знаков, количество до 6, скидка до 2. Денежный итог — 2 знака,
  округление half-up на уровне строки после скидки. Общие суммы — сумма строк,
  а не повторный расчёт от суммарной базы. Ограничить диапазон и число строк
  (1000); превышение — ошибка, не обрезание/молчаливое округление.
- Для `net`: округлить `qty × unitPrice × (1-discount/100)` до копеек → net;
  округлить `net × rate/100` до копеек → vat; gross = net + vat.
- Для `gross`: сначала округлить gross после скидки; vat = округлённое
  `gross × rate/(100+rate)`; net = gross − vat. Для `none`: net=gross, vat=0.
- «Без НДС» отличается от «НДС 0%». Ставки берутся из уже поддержанных
  калькулятором значений, не объявляются автоматически правильными для компании.
  При смешанных ставках показывать отдельные суммы НДС по ставкам.
- Обязательны номер, дата, предмет, названия сторон, хотя бы одна полностью
  заполненная позиция. Номер-дубль у того же исполнителя — предупреждение.
  Нулевая итоговая цена требует явного подтверждения. Просроченный срок действия,
  пустые условия/подписант — предупреждения с точным смыслом; не скрытая автоподстановка.
- Любая ошибка содержит переход к полю. Показанные суммы, preview, DOCX и PDF
  используют один расчётный результат `proposal-pricing/1`.

## 6. Шаблоны, preview и экспорт

- Два встроенных шаблона: «Стандартный» (реквизиты, адресат, вступление,
  таблица, итоги, условия, контакт, подпись) и «Краткий» (те же обязательные
  данные, более компактное оформление). Не скрывать налоги/итоги ради компактности.
- «Сохранить как шаблон» сохраняет оформление и типовые тексты/условия, но не
  заказчика, конкретные цены, предмет, подпись и внутренние заметки. Перед
  сохранением показывается точный состав. Встроенные шаблоны неизменяемы.
- В КП хранится снимок шаблона. Изменение шаблона не меняет старые КП.
  Логотип: PNG/JPEG, ≤ 5 МБ, проверка декодирования/размеров; копия-вложение.
- Один генератор делает DOCX из публичного DTO; встроенный LibreOffice
  преобразует этот DOCX в PDF в приватной временной папке. Клиентский
  предпросмотр показывает именно полученный PDF, а не похожую HTML-страницу.
  Страница A4, повтор заголовка таблицы, номера страниц; неразрывные реквизиты
  и итоговый блок; длинные позиции корректно продолжаются на следующем листе.
- Preview имеет загрузку, ошибку, отмену/повтор; устаревший ответ не заменяет
  новый. Показана ревизия/отметка «предпросмотр устарел» после изменения.
  Экспорт фиксирует текущий валидный снимок, блокирует повторное нажатие,
  не завершает успехом до фактической проверки файла.
- Экспорт DOCX доступен при недоступной PDF-конвертации с честной ошибкой PDF;
  не выдавать HTML под расширением DOCX/PDF. Не загружать внешние шрифты/ресурсы.
- Имена: `КП-<номер>-v<ревизия>-<заказчик>.docx/pdf`; безопасная длина/символы.
  Занятое имя не перезаписывать: предложить свободное с номером, подтвердить путь.
  Запись во временный файл рядом с назначением, затем безопасная публикация;
  сбой/междисковый перенос/SMB не оставляет частично готовый результат.
- Приложения по явному выбору: отдельный ZIP с КП, перечнем и выбранными файлами,
  не вложенные скрытые данные DOCX. Проверка наличия/хеша; отсутствующее не
  пропускается молча. Не обещать подпись или отправку после экспорта.

## 7. Сохранность, сеть и совместимость

- Новый аддитивный модуль `commercial-proposals`, отдельная новая база с уже
  существующей общей схемой records/drafts/history. **Не менять SCHEMA_VERSION,
  имена, схему и данные прежних семи баз; не смешивать КП с payload закупок.**
  Создаёт новый модуль только редактор; viewer старой папки без нового модуля
  видит «КП пока нет», не пытается создавать файлы и не выдаёт ошибку всей базы.
- Добавить модуль в whitelists, backup/restore, archive, аудит вложений,
  глобальный поиск и центр состояния; покрыть roundtrip старой/новой копии.
  Восстановление старой копии без модуля КП не должно удалять уже существующий
  модуль КП молча. Не поддерживать редактирование одной папки смешанными версиями
  как гарантированный сценарий; старые приложения новые данные не видят.
- Записи шаблонов в том же новом модуле с `kind:'template'`; все списки
  фильтруют discriminator. IDs UUID. `StoredRecord`/история — существующий API.
  Не удалять файлы, на которые ссылаются старые снимки/версии.
- Черновик: сохранять серийно под `proposal:<id>` только редактору; явное
  «Сохранить» пишет карточку, затем очищает соответствующий черновик.
  Ошибка чтения черновика запрещает запись поверх него; ошибка записи оставляет
  форму. При смене инструмента открытое КП остаётся; при смене workspace —
  вопрос о несохранённом, отсутствие переноса данных в другую папку.
- Viewer может просматривать и экспортировать сохранённое КП. «Создать локальную
  копию» явно открывает несохраняемый в общую базу редактор и локальный экспорт;
  не менять общие статусы, шаблоны, номера/историю. Локальные изменения хранятся
  только в памяти окна; выход предупреждает. Не писать скрыто в сетевую папку.
- Потеря редакторского доступа блокирует общую запись, не уничтожает форму;
  доступ повторно проверяется в backend перед записью. Никаких новых паролей
  и обходов текущего lock/owner механизма.
- Первая сохранённая карточка имеет revision 1. Черновик и повторные сохранения
  чернового КП не создают новую коммерческую редакцию. Изменение готового/отправленного
  КП — «Создать новую редакцию»: новый record ID, тот же familyId, revision+1,
  status=draft; старая редакция остаётся без изменения. Копия — новый familyId,
  revision1 и новый номер. Экспорт не означает готовность/отправку автоматически.

## 8. Защита внутренних сведений

Экспорт/preview получают только `ProposalPublicDocument`, построенный whitelist
функцией. Не передавать калькулятор целиком, `source`, `internalNote`, маржу,
себестоимость, расходы/агентов, ставки финансирования, конкурентов, рабочие пути,
учётные имена, историю и невключённые вложения. Экспортный backend повторно
валидирует DTO. Не добавлять эти данные в комментарии/XML/метаданные/имена файлов.
Поле примечаний калькулятора не переносится: оно может содержать внутренние сведения.
Низкая рентабельность видна редактору, но не впечатывается в клиентское КП.
Явно введённый пользователем клиентский текст не «очищается» эвристически молча.

## 9. Acceptance / обязательные тесты

1. Новый КП вручную → две строки → сохранить → повторно открыть; все значения
   сохранены, исходные компании/закупка/калькулятор не изменились.
2. Handoff от маржи использует вычисленную цену, а не `proposedPrice`; handoff
   из несохранённого расчёта помечен; неправильный расчёт не создаёт КП.
3. НДС net/gross/none/0%, смешанные ставки, 0.1×0.2, дробные количества,
   скидка 100%, большие суммы: одинаковые копейки в UI/DOCX/PDF, сумма строк
   совпадает с итогом; NaN/Infinity/невалидные значения не проходят.
4. В каждый закрытый источник поместить уникальные секретные маркеры:
   экспортируемые DOCX (весь ZIP/XML/metadata), PDF (текст/metadata) и пакет
   не содержат ни одного. Приложения только из явного списка.
5. Смена исходной компании/подписанта/шаблона не меняет существующий снимок;
   дата/хеш источника доступны для сравнения, обновление только явное.
6. Готовая/отправленная редакция неизменна; новая редакция/копия имеют
   правильные familyId/revision/номер, история и старые вложения доступны.
7. Отказ сети/диска, двойной Save, закрытие во время сохранения, потеря lock,
   смена workspace, просроченный async ответ: нет потери формы/двойной записи.
8. Viewer читает и экспортирует, локальная копия не пишет в общую папку;
   старый workspace без новой базы открывается без неявной миграции.
9. Backup/restore roundtrip содержит КП, шаблоны и файлы; старая копия не
   стирает новый модуль без отдельного ясного решения; прежние базы побайтово
   не мигрируют из-за установки функции.
10. DOCX/PDF проверены реальным открытием и рендером: 1/20/1000 строк,
    кириллица, длинный номер/описание, переносы, логотип, страницы/итоги,
    пустые необязательные блоки, 1024×720; обе платформы и сетевой путь.
11. Занятое имя, повреждённое/отсутствующее приложение, недоступный LibreOffice,
    отмена экспорта: ни ложного успеха, ни замены пользовательского файла.

## 10. Разбиение реализации

1. Типы, decimal pricing, валидация, public DTO, handoff, unit-тесты.
2. Новый аддитивный storage-модуль, backup/archive/history/attachments, тесты совместимости.
3. Реестр/редактор/шаблоны, состояния ошибок/прав, сохранение черновика.
4. Общий DOCX→PDF renderer, настоящий preview, безопасный экспорт/пакет.
5. Интеграция с калькулятором/закупками/поиском/центром состояния и нативный QA.

Не объявлять конструктор готовым после одной HTML-страницы или без проверенных
DOCX/PDF. До включения handoff исправить найденные ошибки исходных расчётов/готовности.
